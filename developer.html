路径 A · 公开仓库

在本地运行 Pages 前端

可复现

准备 Node.js 24+ 与 pnpm 11.19.0。没有后端时，绑定入口会诚实显示“尚未配置”，其余静态说明、WebUSB 和文件检查仍可使用。

git clone https://github.com/BLACKFirework/OurNotesCacheExporter.git
cd OurNotesCacheExporter
pnpm install --frozen-lockfile
pnpm test
pnpm dev

生产构建前必须设置精确 HTTPS origin；不要把本机地址、账号、token、用户文件或临时 ticket 提交到仓库。

路径 B · 仓库协作者

运行自己的本地 QQ bot

需要后端源码
  1. 1
    准备 QQ 运行端

    安装并登录 NapCat；建议使用专门的 bot QQ，先在本机测试。

  2. 2
    配置 OneBot

    新增 WebSocket Server，监听 127.0.0.1:3001，消息格式选 array。

  3. 3
    安装依赖

    在后端仓库的独立虚拟环境安装 bot 与预览 requirements。

  4. 4
    设置私有环境

    填写自己的 OWNER QQ、OneBot URL 和可选 token，不写进源码。

  5. 5
    启动并实测

    启动 runner，从另一个 QQ 发送 /help、谱面或算分命令。

python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-bot.txt -r requirements-preview.txt
$env:OURNOTES_OWNER_QQ_IDS = "你的QQ号"
$env:OURNOTES_ONEBOT_URL = "ws://127.0.0.1:3001"
$env:OURNOTES_ONEBOT_TOKEN = "你在NapCat中设置的token"
.\.venv\Scripts\python -m bot.live_onebot

当前限制：完整后端仓库尚未作为公开发行包提供。没有仓库权限的开发者目前只能运行公开前端，不能按本页复现 bot 的全部命令与主数据。

路径 C · 完整绑定

增加卡库绑定服务

进阶

必须准备

  • 独立的 dev / test / prod 数据根
  • 生产 HTTPS origin 与受控 CORS
  • 一次性 ticket、会话和通知队列
  • 定期备份与可回滚提交

仅按来源准备

  • BHK 登录：只在私有后端接收凭据
  • Moenotes：自己的 client ID 与 Secret
  • 文件导入：明确大小和格式上限
  • 无需用到的来源不要配置

禁止公开

  • OneBot token、API Secret 和密码
  • QQ 关联、快照、上传与数据库
  • 完整 ticket、Authorization 和原始响应
  • 生产日志与本机绝对路径

前端发布不会启动或重启本地后端。临时隧道变化后，要更新 Actions repository variable 并重新发布；地址公开可见，不能代替鉴权。

维护者流程

测试通过后再发布

  1. 独立 worktree：从目标提交建分支，不在生产目录直接开发。
  2. 合成测试：测试数据根不能读取生产快照或通知真实 QQ。
  3. 门禁：后端相关测试、前端测试、类型检查、生产构建与公开扫描全部通过。
  4. 界面验收：检查桌面、手机、离线、无效、过期、确认和完成状态。
  5. 版本发布：合并公开前端后创建 shizukubot-v* 标签，由 Actions 部署 Pages。
  6. 线上核对：确认页面版本、后端健康兼容性和一次性链接，不把本地通过当成生产成功。

开发者 FAQ

开始前需要知道

能不能只在自己的 QQ 上运行？

可以。NapCat 登录自己的 bot QQ，本地 runner 连接它的 OneBot WebSocket 即可。建议先使用专门账号并只在本机测试；OWNER 列表应只填你控制的 QQ。

为什么不直接给 Docker 一键部署？

完整后端依赖尚未从研究数据、运行目录和私有配置中整理成干净公开包。现在发布镜像会让人误以为主数据、认证来源和卡库导入都能公开复现。

必须一直开着电脑吗？

本地 OneBot runner、绑定后端和临时隧道都依赖运行它们的电脑在线。只有静态 Pages 可以持续访问。

开发者页面会暴露生产配置吗？

不会。本页只列出变量名称和占位值。生产 origin 存在 GitHub Actions repository variable；Secret、token、用户数据和运行目录不进入公开构建。
